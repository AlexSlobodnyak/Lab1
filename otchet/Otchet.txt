ХОД РАБОТЫ
================================================================================

1. АРХИТЕКТУРА ПРИЛОЖЕНИЯ
   Спроектирована архитектура по паттерну Model / ViewModel / View:
   * Model   : содержит чистую математику, не зависит от интерфейса.
   * ViewModel : хранит состояние и связывает Model с View через сигналы.
   * View    : отвечает исключительно за визуальное отображение данных.

2. СЛОЙ MODEL (МАТЕМАТИКА)
   Все преобразования реализованы вручную, без внешних библиотек. Модули:
   * illuminants.py : Источники света D65, D50, E и вычисление белой точки XYZ.
   * gamma.py       : Прямое и обратное sRGB гамма-преобразование.
   * rgb_xyz.py     : Построение матриц RGB <-> XYZ на лету из первичных 
                      координат sRGB и белой точки выбранного источника.
   * xyz_lab.py     : Преобразования XYZ <-> LAB по стандарту CIE 1976.
   * cmyk.py        : Алгоритмы цветоделения UCR (Under Color Removal) и 
                      GCR (Gray Component Replacement).
   * gamut.py       : Стратегии приведения цвета к охвату sRGB: clipping 
                      (отсечение) и scaling (масштабирование).
   * converter.py   : Фасад, объединяющий всю математику в единый интерфейс.

3. СЛОЙ VIEWMODEL (ЛОГИКА СОСТОЯНИЯ)
   * Реализован класс ColorViewModel. Хранит текущий цвет в формате RGB.
   * Вызывает преобразования через ColorConverter.
   * Эмитит сигналы color_changed (изменение цвета) и warning_raised 
     (предупреждение о выходе за охват).

4. СЛОЙ VIEW (ИНТЕРФЕЙС)
   * GradientSlider : Кастомный слайдер, перерисовывающий градиентную подложку 
     при каждом изменении цвета с учётом остальных координат для визуального 
     предсказания результата.
   * ColorPanel     : Панель одной цветовой модели с полями ввода и слайдерами. 
     Не выполняет расчёты, эмитит сигнал values_edited и принимает новые 
     значения через set_values (без рекурсивного пересчёта).
   * MainWindow     : Главное окно, объединяющее три панели (RGB, LAB, CMYK), 
     элементы управления (источник света, алгоритм CMYK, стратегия охвата), 
     превью цвета и кнопку вызова системной палитры.
   * Динамическая связка: изменение в любой панели пересчитывает цвет и 
     обновляет две другие. Активная панель не перезаписывается, что исключает 
     «подпрыгивание» введённых значений.
   * UI/UX          : Пропорциональное растягивание интерфейса (панели и 
     слайдеры равномерно заполняют пространство). Визуальное предупреждение 
     о выходе за охват sRGB (красная плашка на 3 секунды + сообщение в статус-бар).

5. ТЕСТИРОВАНИЕ И СБОРКА
   * Написано 45 автоматических тестов (pytest), покрывающих:
     - RGB <-> XYZ при D65, D50 и E;
     - XYZ <-> LAB;
     - RGB <-> CMYK с алгоритмами UCR и GCR;
     - Стратегии clip и scale, круговые преобразования и сигналы ViewModel.
   * Все тесты успешно проходят.
   * Собрано исполняемое приложение (.exe) для Windows через PyInstaller.
   * Исходный код размещён в репозитории GitHub.

В ходе лабораторной работы было разработано приложение, представляющее цвет 
одновременно в трёх моделях (CMYK, LAB, RGB) в соответствии с вариантом №10. 

Реализованы все требования подгруппы 10А:
* Ручной расчёт всех преобразований без жёстких констант.
* Поддержка стандартов освещения D65/D50/E с пересчётом матриц на лету.
* Алгоритмы цветоделения UCR и GCR.
* Стратегии выхода за охват: clipping и scaling.
* Динамические градиенты на слайдерах для улучшения UX.

Код строго разделён на слои Model / ViewModel / View, математическая часть 
полностью покрыта автоматическими тестами. На практике закреплены теоретические 
знания о цветовых моделях и алгоритмах преобразования между ними.
